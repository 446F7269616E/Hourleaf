# Hourleaf 架构与数据契约

## 目标

Hourleaf 是本地优先、跨浏览器的网站专注扩展。核心目标是准确计时、确定执行用户规则、按需授权网站，并让站点适配可以独立演进而不进入通用内核。

## 分层

页面品牌、工具栏与 favicon 共用选定的 C 版叶片沙漏系列；品牌渲染统一由 `src/ui/brand-mark.ts` 提供，资源尺寸和导出方式见 [图标规范](./ICONS.md)。

```text
popup / dashboard / plan / options / block / home / end
                    │
                    ▼
           application services
          ┌─────────┴──────────────┐
          ▼                        ▼
 generic focus core        local module gateway
          │           ┌────────────┼────────────┐
          │           ▼            ▼            ▼
          │      CSS/selectors              User Scripts API
          └───────────────┬───────────────┘
                    ▼
      storage / permissions / scripting / idle
                    ▼
     Chromium / Firefox / Safari build adapters
```

- `src/shared` 与 `src/core` 只包含通用领域模型、消息和浏览器端口。
- `src/background` 是可恢复的协调层，不依赖常驻 Service Worker。
- `src/content` 只报告可见性、焦点和路由状态，并渲染核心专注界面。
- `src/modules/local` 负责有界本地文件格式、双重校验、存储和平台执行适配。
- `optional-modules` 是仓库侧示例目录，不进入商店包，也不被运行时联网读取。
- UI 只调用版本化消息，不直接读写任意 storage key。
- 平台差异由浏览器适配层与构建 manifest 处理，业务层不按 UA 分支。

## 通用网站模型

设置 schema v4 使用三个稳定标识：

- `SiteId`：用户授权的网站作用域；普通网站是精确来源，审核过的站点家族使用规范来源；
- `TargetId`：同一网站内可独立应用时间规则的目标；
- `SiteModuleId`：经过审核的可选站点能力包。

核心只保存来源、主机名和经过校验的匹配范围，不保存普通浏览的路径、查询参数或页面标题。新增网站时必须由用户点击触发权限请求。普通网站始终授权精确 `${origin}/*`；只有 `src/shared/site-scope.ts` 中显式审核的站点家族才能扩展范围，例如 Bilibili 使用 `https://*.bilibili.com/*` 同时覆盖根域与其 HTTPS 子域。不得根据任意输入自动推断 eTLD+1 或泛化子域，以免跨租户或扩大权限。后续同类网站通过站点家族注册表新增数据定义，权限、URL 解析、计时、popup、访问确认和标签页关闭统一复用同一作用域函数。后台只为仍持有权限的网站注册动态 content script，并在新增配置或重建注册时把同一脚本安全地补注入已经打开的匹配标签；内容入口以隔离世界内的运行标记保证幂等，避免重复心跳和监听器。撤销权限或删除网站后停止计时与拦截。

普通网站默认有一个整站目标。站点模块可以声明多个稳定目标，但不能扩展到 manifest 未声明的主机。

## 商店核心与本地模块协议

商店包不包含网站专用可执行模块。旧 `SiteModuleDescriptor` 只保留迁移与源码兼容，发布目录为空，构建脚本不再输出 `modules/<site>.js`。

`LocalModuleDefinition` 是本地文件经导入器解析后的规范化声明：

- 固定模块 ID、版本、名称和精确 HTTP(S) 来源；
- `timed | always-allow | always-block` 域名策略；
- 有界元素选择器和自包含 CSS；
- 非空 DNR 规则被拒绝，避免域名级规则越过精确 origin 边界；
- 可选用户脚本文本，只能交给浏览器 User Scripts API。

导入器只读取用户在同一次文件选择中提供的 `.json`、`.css`、`.user.js`。清单不能包含远程依赖，核心不提供模块 URL 安装、GitHub API、自动更新、`eval`、`Function`、远程 `import` 或解释器。

发布形态：

- 每个平台只发布一个 Hourleaf 扩展，不要求用户安装第二个扩展；
- 模块先显示网站范围与能力，再由用户点击申请精确来源权限；
- 元素隐藏/CSS 由通用 content script 应用，CSS 远程加载语法被拒绝；
- `src/content/local-page-rules.ts` 统一渲染本地样式，并按模块的 `shadowRoots` 声明同步到开放根；后台保留每个模块自己的规则边界。仅扫描声明宿主和新增子树，挂载事件处理晚附着的根，页面状态刷新兜底；规则更新、宿主移除和停用清理旧样式，不依赖已经停用的历史站点适配器。
- Chromium/Firefox 固定使用隔离 `USER_SCRIPT` world、顶层 frame、`document_idle`；
- Safari 商店构建拒绝用户脚本文件；
- 停用/删除模块会注销其用户脚本，本地文件内容随删除移除；初始化同时清理旧版本遗留的自有 DNR 规则。

本地 Chromium Debug 版由同一构建入口生成，但只在构建期内联 `optional-modules/` 当前内容并预置对应受管网站。Debug 产物默认写到仓库外，使用独立名称、固定测试 host 权限和可验证 marker；正式构建注入空预置且发布门禁拒绝任何 Debug manifest 或 marker。Debug seed 只清理自身记录的陈旧模块 ID，不触碰测试者手动导入的其他模块。详见 [LOCAL_DEBUG_BUILD.md](./LOCAL_DEBUG_BUILD.md)。

完整格式和平台能力矩阵见 [LOCAL_MODULES.md](./LOCAL_MODULES.md)。

## 计时模型

累计时间必须同时满足：

1. 当前来源已由用户配置和授权；
2. 对应网站与目标已启用；
3. 页面可见且窗口聚焦；
4. 设备未空闲或锁定；
5. 页面未被计划或时间规则阻断。

content script 发出 `start / heartbeat / route / stop`。后台串行处理会话事件并按会话 ID 去重，心跳间隔超过上限视为中断；每次会话事件必须先完成上一段 `TargetId + TimePeriodId` 聚合写入再响应，使紧随其后的规则判定读取到同一权威用量。跨本地午夜拆分后写入每日桶，周/月/年统计只从每日桶汇总，不保存页面 URL。

## 时间规则

规则是纯函数：`weekday + local time + target settings + period usage + runtime -> allow | block | defer`。

- 每个目标拥有多个 `TimePeriodSettings`；新目标默认每天 `00:00–00:00` 全天时段，额度为空、1 组，按本地 0 点刷新；
- 网站和目标级 `enabled` 仅保留为旧数据兼容镜像并在读取时归一为 `true`；用户可见的启停边界只有 `timePeriods[].enabled`，避免隐藏总开关覆盖时间段状态；
- 先按星期，再按 `HH:mm` 半开区间匹配；相同起止时间表示所选日期全天，跨午夜按开始日延续；
- 重叠时优先级为 `always-allow > always-block > timed`，未命中任何时段时不可用；
- `timed` 时段拥有独立额度和 1–24 个等分组；组运行状态与统计分离，避免污染长期设置；
- `src/shared/time-period-presets.ts` 把内置及自定义预设转换为全新的普通 `TimePeriodSettings[]`，因此每次应用均有独立运行时 ID 和额度。应用预设时仅替换完全未修改的系统全天时段，其他已有时段一律保留并追加。内置预设来源不写入存储；用户命名的自定义预设保存为 schema v5 的 `customTimePeriodPresets`，最多 32 个、每个最多 16 段，并随配置备份往返。三餐预设为 07:00–09:00、12:00–14:00、18:00–20:00 各 30 分钟 1 组；两段分割为 06:00–12:00 与 12:00–18:00 各 30 分钟 2 组；午前、午后、晚间分别在 06:00–12:00、12:00–18:00、18:00–00:00 提供 60 分钟 3 组；早起鸟为 00:00–06:00、06:00–12:00 各 30 分钟 2 组，夜猫子为 12:00–18:00、18:00–00:00 各 30 分钟 2 组；
- `lenient` 到期只提醒，`flow` 到期允许一次 1–15 分钟或视频结束延时，`strict` 直接进入结束页；分钟选择器只显示时长，“再用 / Use”作为控件外标签；
- 每个使用分组耗尽都会进入结束页，明确显示已使用组数与总组数并询问是否开启下一组；下一组可直接开启、等待、完成数学题或比对本地 SHA-256 密码校验值。直接开启也必须由用户在结束页点击确认；等待只能在已到达真实分组边界后开始，所有解锁方式成功后均通过已按网站作用域校验的原始地址返回，不依赖易失的历史缓存恢复；密码只增加操作摩擦，不是账户安全边界；
- 结束页是独立扩展页面，不跳转到设置/仪表盘主页面；默认显示当日摘要，可改为激励文字或简洁提示。无法继续时主操作是关闭当前配置作用域内的全部网站标签页，并同时关闭当前结束页；计划事项按该事项的精确来源关闭，不接受页面传入的任意通配范围。
- 每个网站可独立开启“访问前确认”及 0–60 秒等待，并可保存一条最长 160 字符的可选自定义打开提示语；它只在其他规则已允许访问时生效，不复用结束页分组解锁状态。确认授权只覆盖当前标签页在该 origin 的连续访问，离开 origin、关闭标签或更改网站策略后失效；会话存储仅保存 `tabId + SiteId + origin + 策略版本`，不保存页面路径。

## 计划

计划清单接受用户主动添加的 HTTP/HTTPS URL，保存规范化 URL、来源、标题、顺序、完成状态、事项级预定时长和到期模式。只有用户点击“开始”时才请求该事项精确 origin 的可选网站权限；后台二次验证权限后，用唯一固定 ID 为当前 active grant 注册 `content.js`，不会批量注册整个队列，也不会改动 focus 网站的注册。开始项目时创建精确绑定 `itemId + URL identity + expiresAt + completionMode` 的授权；删除、完成、修改、停止或到期会撤销授权并对该固定注册执行 reconcile。后台启动时只会为仍有效或等待一次心流选择的授权恢复注册。可选的 `autoCompleteOnStart` 默认关闭。

计划到期沿用宽容 / 心流 / 严格语义。心流授权只能延时一次，分钟选项限制为 1–15；“视频结束”是独立的显式授权状态，不使用分钟过期时间，只由内容脚本绑定的当前视频在 `ended` 时发送 STOP，或由其他显式停止操作撤销。存储使用 `Number.MAX_SAFE_INTEGER` 作为不触发普通到期分支的持久化哨兵值，旧版 15 分钟视频结束授权在读取时迁移为该状态。

计划页不暴露独立的“计划模式”启停开关。开始待办是进入计划访问的唯一显式入口；有效授权完成、删除、修改或到期后同步退出计划访问，避免形成没有退出路径的拦截状态。`PlanModeSettings.enabled` 暂时只作为兼容字段和运行时状态保留。

计划列表使用自适应网格展示待办，已完成区域默认折叠并在页面会话内保留展开状态。思维导图使用独立的大画布 viewport：节点按统一列宽和真实内容高度参与布局，长链接最多显示两行且不越过节点；画布支持空白区域拖动、指针中心缩放、键盘平移和 `fit view`。适配算法只依赖场景与 viewport 的实际边界并保留内边距，最低概览比例覆盖 500 个事项；分支主干按折叠或展开后的真实节点中心重新测量，避免固定百分比连线错位。普通滚轮保留页面滚动，只有 `Ctrl/⌘` 加滚轮执行画布缩放。实现避免引入重量级图编辑器依赖。

站点模块可提供更严格的身份，例如 Bilibili 模块把视频规范化为 BVID/canonical URL。核心计划不能依赖任何特定网站标识。

设置中的“计划访问独立计时”默认开启。开启时，只有精确匹配当前 active grant 的页面可绕过配置时段，且该段访问不写入配置的 `TargetId + TimePeriodId` 用量；关闭时，配置判定与计划授权必须同时允许，用量继续归入配置计时。独立计时不扩大 URL identity 或 host permission。

每个计划事项必须持久化自己的预定时长。可选的 `pauseOnVideoEnd` 会复制到 active grant；内容脚本只能对当前精确事项发送视频结束 STOP，后台再次校验 `itemId + URL + grant flag` 后撤销授权。它与到期后心流模式的“播放结束后继续”是两个独立状态。

## 存储与迁移

为兼容既有安装，逻辑键暂时保持 `bilifocus.*`；品牌变更不直接重命名持久化键：

- `bilifocus.settings.v1`：当前值 schema v4；
- `bilifocus.usage.v1`：当前值 schema v3，权威字段为 `byTarget` 与 `byPeriod`；
- `bilifocus.temporary-access.v1`：当前值 schema v2；
- `bilifocus.plan-queue.v1`；
- `bilifocus.plan-access.v1`。
- `hourleaf.period-runtime.v1`：schema v1，保存每日分组解锁和一次性心流延时状态；
- `hourleaf.modules.v1`：旧预装模块迁移状态；商店构建初始化时清理；
- `hourleaf.local-modules.v1`：schema v1，保存用户本地导入的规范化模块与启用状态。

设置页“数据管理”提供纯本地 JSON 备份，格式为 `hourleaf.configuration-backup` schema v1。备份只包含规范化核心设置（包括一键预设或自定义产生的普通时间段）、计划清单，以及已安装本地模块的 `id + version + enabled + disabledFilterGroupIds` 安全偏好；不包含使用历史、预设来源标记、临时/计划活动授权、分组运行态、访问确认会话或本地模块 CSS/用户脚本源码。导出和导入使用同一严格校验器与 16 MiB 上限，因此成功生成的同版本备份必然可以被同版本解析器读取。

恢复前，设置页“数据管理”在明确的确认按钮手势内一次申请备份网站与“本机已安装、版本完全一致且将恢复为启用”的模块所需精确来源权限；任一权限缺失时不写入。设置页先等待在途设置写入完成，后台再结束并落盘旧计时段，用单次 `storage.local.set` 原子替换设置、计划队列和安全模块偏好，同时关闭计划模式并清空计划授权、临时访问和时段运行态。持久化成功后重建受管网站 content script、本地用户脚本、计划注册、访问确认和工具栏状态；运行态协调失败只作为成功响应中的警告，不把已经完成的恢复误报为“未写入”。未安装或版本不同的模块偏好会跳过，绝不借备份安装、替换或启用不同代码。

恢复不会主动撤销浏览器中原有但已不再出现在配置内的 host permission，以免误伤仍由本地模块或用户其他显式授权使用的同一来源；动态注册会按新配置立即移除，因此这些保留权限不会继续激活 Hourleaf 内容脚本。用户仍可在浏览器扩展权限面板手动撤销。

v1/v2 的 Bilibili 板块、计划和内容降噪设置继续作为只读兼容 capsule 保留，但商店构建不激活旧站点模块。迁移必须幂等、有界并保留无法识别的数据；损坏值回退到安全默认值。计划视图偏好使用 `hourleaf.plan.view`，仅允许 `list | mindmap`。

## 消息边界

访问确认只能由同一标签页中的扩展确认页授权，后台会再次匹配已配置网站作用域、当前 origin、策略版本和等待截止时间。

消息使用 `{version, requestId, type, payload}`。后台必须验证发送方、URL 来源、权限、字段、长度、枚举与数组规模。网站心流消息还要校验发送标签页同源、目标和时段；计划判定/延时/停止消息校验 sender 与声明 URL 同源且当前 origin 仍有 host permission，但不要求该 origin 已加入 focus 网站，精确事项与 URL 校验仍在 `PlanService` 边界完成；分组解锁仅允许扩展页。本地模块在导入器和后台边界分别规范化；content script 只能读取当前 URL 对应的合并 CSS/选择器，不能读取用户脚本、全量模块、全量设置/历史、请求任意 Chrome API 或传入 storage key。扩展页才能执行模块导入、站点 CRUD、计划 CRUD 与数据清理。

## UI 与文案

固定居中置顶导航顺序为：仪表盘、计划、配置、屏蔽、设置。品牌、主导航和页面操作分别占据顶栏左、中、右区域；最右侧问号按钮提供五个主页面的简短说明；窄屏降级为五等分横向导航。五个完整页面共享标题字号和页首位置；配置、屏蔽、设置不重复显示页面级副标题。各页职责保持单一：仪表盘只读展示聚合统计，计划页只承载待办/思维导图，配置页只管理网站时间段，屏蔽页负责本地模块导入、网站屏蔽内容分组和 GitHub 下载/开发规范入口，设置页只管理语言、主题色、计划选项、结束页与数据。主题色是规范化设置，以设计 token 驱动所有完整页面的强调色方案。配置页不提供人工保存按钮：限制模式和时间段变更通过串行领域消息实时持久化，状态区只反馈保存中、已保存或失败，且不得用完整设置快照覆盖其他页面的并发设置。所有页面通过 `src/shared/i18n.ts` 的稳定键共享简体中文/英文资源，manifest 使用标准 `_locales`；站点模块只提供数据和能力，不拥有独立视觉系统。用户可见文本遵守 [UX_WRITING.md](./UX_WRITING.md)，不显示内部 provider、协议或调试建议。

配置页编辑采用即时调度的自动保存，并用单一串行写循环合并快速连续操作；写入期间的新编辑会在前一次完成后继续保存，不显示导航中的保存状态或手动保存按钮。限制模式通过 `UPDATE_MANAGED_SITE` 保存，时间段通过 `UPDATE_SITE_TARGET` 保存，避免陈旧配置页覆盖语言、结束页等其他设置。限制模式与网站身份分别使用独立卡片，避免与时间段开关混淆。时间段区将强调色赋予“一键添加”，普通“添加时间段”为次操作；一键添加弹窗左侧选择预设或进入自定义编辑，右侧用 24 格色条和文字清单同时预览覆盖小时、限额与分组，并在预览下方固定显示“添加预设”按钮，灰色明确表示不可使用。设置页内容在宽屏居中，字段使用稳定的说明列/控件列网格，窄屏降为单列；配置导入和导出只出现在“数据管理”。

仪表盘的日/周/月/年视图与计划页的列表/思维导图视图都使用带可见“视图”标题的单选按钮组。仪表盘在页面统计内容上方显示当前日期范围，日/周/月趋势按日汇总，年趋势按月汇总。访问前确认使用独立卡片并位于限制模式之上，等待时间和自定义提示语仅在勾选“访问前确认”后显示；取消勾选时隐藏并禁用字段，保留已输入的值。

Popup 每次刷新都重新查询当前活动标签与计划状态，并监听标签激活、URL 变化、可见性与设置变化；服务端数据以 5 秒为上限对齐，两次对齐之间仅在已确认正在计时时本地递增展示，不频繁写存储。弹窗以紧凑的当前网站摘要呈现当前组/总组数，并按排序展示至多三项未完成待办及其余数量；主操作固定进入计划页面。单组时只显示一个剩余时间；多组时显示本组剩余、当前时段总剩余和该目标全部有限时段的今日总剩余。普通时段和分组用量均从 `PageDecision.activePeriodId + UsageSummary.byPeriod` 计算，不读取已废弃的目标级日限额；进入分钟制心流延时或临时访问后，当前时段剩余改用权威运行时到期时间，视频结束延时因没有确定分钟数而不显示误导性的 `0`。Popup 与完整页面同样从规范化主题设置应用设计 token。`showRemainingMinutesOnIcon` 默认开启；后台为每个活动标签设置剩余整分钟 badge，并在心流运行时、计划授权、用量或设置变化后立即重算。独立计时开启时角标只显示计划剩余时间；关闭时，配置时间与计划时间同时生效并显示较早截止的一项。未配置、无限额、非 HTTP(S)、全局暂停或关闭该选项时清空。

限制模式和计划到期方式共享“短模式名 + 选择控件下方常显说明”的表达：选项只显示宽容、心流、严格，说明随选择即时更新。设置页用原生 `details / summary` 组织常规、结束页面和数据管理，保留键盘与读屏原生语义；插件图标剩余分钟开关默认启用。屏蔽页的模块导入弹窗只保留文件选择、结构化预览和必须确认的安全免责，不重复展示格式规范或内部风险标题。

所有设置写入，包括站点和模块的新增、删除及清单应用，都通过 `SettingsRepository` 的同一读改写事务队列；领域服务不得在队列外读取后再提交整份旧快照。限制模式更新只修改站点模式，不重放模块清单或重建无关注册。

## 访问确认与计划屏蔽更新（2026-09-12）

确认页通过 `tabs.getCurrent()` 获取自身标签 ID。后台验证发送方为自身 `end.html`，其 hash 中的来源、返回地址及网站 ID 与请求一致，再核对标签存在以及原先的待确认授权、origin、策略版本和等待截止时间。Chromium 可能省略扩展页的 `sender.tab`，没有广泛 `tabs` 权限时也可能省略 `tabs.get()` 的 URL；不能把缺失字段当作标签已离开。URL 可用时额外拒绝导航变化，不新增权限。

设置项 `planMode.enableAllBlocking` 默认开启，仅在有效计划授权存在时使用计划屏蔽偏好。`LocalModuleInstallation.planPreferences` 缺省表示模块及内容组全部开启，普通 `enabled / disabledFilterGroupIds` 保持原值；`modules/local/profiles.ts` 负责只读投影。屏蔽页自动显示和编辑当前上下文，不添加设置组切换控件；写请求携带快照的 `profile`，后台拒绝上下文已变化的陈旧写入。模块更新、后台重启和备份恢复保留两组偏好，新增分组在计划中默认开启。

计划启停、到期及新选项切换刷新页面 CSS/Shadow DOM，并串行同步用户脚本注册。计划中仅注册已获精确来源权限的脚本，不自动安装模块或申请权限。域名访问策略继续使用普通启停状态，避免开启内容屏蔽反而阻断计划目标。浏览器注销注册不撤回已执行脚本创建的页面监听器，继续遵守已有用户脚本生命周期。

选择屏蔽上下文调用 `plan.getState({ reconcile: false })`，只读观察，避免在计划授权/模式分步落盘期间清理正在创建的授权。配置备份包含两组纯数据偏好；旧备份缺少新设置时补默认值，其余字段仍严格验证，不引入可执行源码。
