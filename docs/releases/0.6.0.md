# Hourleaf 0.6.0 History

Historical feature record for the 0.6.0 series, dated October 14, 2026. For the current release, see [1.0.0](./1.0.0.md) and [current features](../FEATURES.md). This record does not describe the current store candidates or confirm that a store version was published.

## Website rules and access

- Independent windows with enable state, weekdays, start/end times, behavior, allowance, and groups; changes save immediately.
- Meal, two-session, morning, afternoon, evening, early-bird, and night-owl presets, plus named reusable custom combinations.
- Overlap priority: always available, always blocked, then limited use. No windows, or all disabled, allows unlimited ordinary use while retaining usage tracking, filtering, and schedules.
- Shared access confirmation and group-unlock policy: a 30-second default wait followed by confirmation, immediate confirmation, equations, calculus, or a password. Confirmation is shared within the website's current window unless repeated new-tab confirmation is enabled.
- The website's message switch controls only its text. Time inputs and timestamps use 24-hour time.
- Lenient, Flow, and Strict handle each group ending. Flow permits one extension of 1–15 minutes or until the current video ends; ordinary extensions do not consume later groups by default.

## Tab-group whitelist

- A whitelist directory alongside websites binds existing browser groups to weekday/time windows.
- During a window, authorized configured websites in the group have unlimited ordinary access without consuming allowances, confirmation, or group pauses. Actual usage remains recorded.
- Content filtering, explicit domain blocks, and plan deadlines remain. Leaving the group or reaching the window's end restores rules and balances.
- Bindings are valid only within the browser session. Group destruction, browser restart, or restoring configuration requires rebinding; rules persist.
- Ordinary closure preserves grouped tabs and tabs with unknown membership. Plan closure follows the item's origin.

## Independent plans

- Items contain a URL, title, goal note, planned duration, expiry mode, and optional video-end pause; bulk add, sorting, completion, and restoration are supported.
- Permission and duration/goal confirmation precede tracking. Plans are independent of ordinary website statistics and allowances; the old independent-timing switch is removed.
- Access belongs to the confirmed tab and exact origin. Same-origin navigation, refresh, and routes retain the deadline; other tabs do not inherit it.
- Leaving the origin, closing the tab, restarting, or ending the visit clears its timer. Returning after expiry clears the old notification and uses ordinary rules. Items and planned durations remain.
- List and mind-map views place completed items in a collapsed bottom section; the map supports dragging, zoom, keyboard controls, and fit-to-canvas.
- Source changes settle the previous tracking interval and remove its video-end listener. Retrying Flow restoration does not grant extra time.

## Filtering and modules

- Content groups reference existing website windows, using only start/end times as daily filtering windows. Weekdays, enable state, and ordinary allowances do not affect filtering schedules.
- Ordinary and plan preferences are independent. Plans use installed modules' plan preferences without automatic installation or expanded permissions.
- Bilibili 1.2.5 includes home, dynamic feed, related-video, and comment filtering, plus a search shortcut. Comment filtering covers featured comments in dynamic video cards; related filtering covers end-screen recommendations and uses a user script to disable autoplay.
- Xiaohongshu, X, YouTube, and Baidu Tieba modules were version 1.0.1. Names, descriptions, and group labels follow the UI language without changing stable IDs or preferences.
- Module packages are separate from the extension. Users download, review, and import local files on the Block page; there is no automatic download or update. See the [module catalog](../../optional-modules/README.md).

## Interface, statistics, and data

- Five pages share centered navigation. Configuration directories scroll independently and use normal document flow on narrow screens. Settings has six categories.
- Simplified Chinese, English, system language, five themes, and system light/dark mode are supported. The toolbar previews today's usage, remaining allowance, and pending items; the badge shows remaining minutes, except for ordinary unlimited or whitelist access.
- The dashboard supports day/week/month/year views. Ordinary pause pages show group balances, 24-hour charts, and website shares; plan pauses retain duration and goal layouts.
- Local JSON backups include rules, custom presets, whitelist windows, plans, and compatible module preferences, excluding statistics, runtime grants, bindings, and module source. Restore requires group rebinding and uses only installed matching-version preferences.
- Disable protection offers waits or a password. Restore defaults and Clear all data require a 120-second wait and specified confirmation text. Restore defaults retains statistics, plans, and modules; Clear all data deletes application data.

## Historical platform and build behavior

This series generated Chromium, Firefox, and Safari candidate ZIPs, separate module ZIPs, and SHA-256 hashes. Chromium scripts required the browser's user-script capability; Firefox used its optional permission and API. Safari rejected script import and execution. **Current 1.0.0 store candidates reject user scripts on both Firefox and Safari.** The whitelist required group APIs and session storage; Safari did not offer group access. Source candidates did not establish store approval or signing.

Local automated validation covered TypeScript compilation and builds; browser behavior required [manual acceptance](../MANUAL_ACCEPTANCE.md). Remote CI retained formatting, types, lint, unit coverage, builds, and packaging. Debug modules, test sites, and fixed permissions were for local sideloading only and excluded from release.
